# 段2の物理メモリ予算

編集中の写真・保っている写真・先回りの解析・プリセットの見本・大きな書き出しは、段2の Worker の中で1つの物理メモリ予算を分け合います（#155）。見積もりと予算の値は `packages/photo-editing/src/develop-engine/develop-engine-memory-budget.ts`、使い方は `develop-engine-worker-core.ts` が正です。

## なぜ高水位で考えるか

wasm の linear memory は free しても縮みません。一度上がった高水位は Worker が終わるまで物理メモリに残ります。予算は「高水位をどこまで上げてよいか」で決め、持つ物の見積もりは、その内側を使い回せるかの判断に使います。Mac の native sidecar は free で OS に返るので、同じ見積もりを sidecar が同時に持つ量として使います。

## 実測

Studio（M1 Max）・Node 24・単一スレッドの wasm（crate 0.26.0）で、場面ごとに別のプロセスで測りました。写真は 2560×1707 の signed RAW の作業コピー（`stage_timing --dump` の合成）と、6000×4000 の JPEG です。高水位の単位は MiB です。

| 場面 | 高水位 |
| --- | ---: |
| 写真を開いて丁寧に描く（開くだけは98） | 148 |
| ＋別の CNR の解析を先に作る | 304 |
| ＋見本の session で同梱のプリセットを全部描く | 521 |
| ＋直前の写真を保つ（今の PC の保ち方） | 688 |
| 書き出しだけ: 作業コピー長辺2048 | 180 |
| 書き出しだけ: 補正を全部使った作業コピー2560 | 804 |
| 書き出しだけ: JPEG 長辺4096 | 209 |
| 書き出しだけ: 補正を全部使った JPEG 長辺4096 | 1,616 |
| 補助の worker（同じ写真を開いて CNR 25 の解析を作る） | 198 |
| 688 を持ったまま補正全部入りの作業コピー2560を書き出す | 1,387 |
| 同じ書き出しを、見本・kept・先回りを手放してから | 973 |
| 688 を持ったまま補正全部入りの JPEG 4096 を書き出す | 2,194 |
| 同じ書き出しを、手放してから | 1,821 |

「補正を全部使う」はマスク3枚・ディテール（シャープ・輝度30・カラー25のノイズ軽減）・遠近・修復・レンズ補正です。保ったまま書いても手放してから書いても、書き出した画素は同じでした。

再現は `packages/develop-engine/tools/memory-budget-bench.mjs` の先頭の手順で行います。Node の数字は端末やブラウザの合否に読み替えません。

## 見積もり

| 持つ物 | 見積もり |
| --- | --- |
| 開いている写真・保っている写真 | 作業画素 × 36 bytes |
| 先回りの解析1件 | 作業画素 × 38 bytes |
| 見本の session | 親の作業画素 × 64 bytes |
| 補助の worker | 作業画素 × 46 bytes |
| 解析の compact bytes | 実際の byte 数（JS に置く） |
| 書き出し1回 | 作業コピーは開く分（× 36）＋描く分。JPEG / PNG は描く分だけ |

描く分は、書き出す画の画素 × (21 ＋ マスク1枚ごと10 ＋ ディテール30 ＋ ノイズ軽減36 ＋ 幾何15 ＋ 修復11 ＋ レンズ15) bytes です。#134 の係数にノイズ軽減を足しました。実測との差は +1〜+14% で、どれも実測を下回りません。画面の「大きく」をスマホで出すかの判断（`browserPhotoExportLargeWasmBytes`）も同じ係数を使います。

## 予算

| 端末 | 合計 | 書き出しの空き | 保つ写真 | 収まらない書き出し |
| --- | ---: | ---: | ---: | --- |
| PC | 1,024MiB | 256MiB | 開いている1枚＋直前の1枚 | 使い捨ての worker |
| スマホ | 768MiB | 192MiB | 開いている1枚だけ | 同じ Worker で全部手放して描く |

合計は Worker の wasm の高水位（native は sidecar が同時に持つ量）、JS に置いた解析の bytes、同時に動く補助の worker の合計の上限です。持つ物の上限は「合計 − 書き出しの空き」です。ただし wasm の高水位がそれより上がっていれば、払った分までは使います。

PC は今の保ち方（688MiB）と解析の bytes（32MiB）が上限768MiBに収まります。長辺2048の書き出しは手放さずに同じ Worker で描けます。スマホは保たない形（521MiB）と解析の bytes（16MiB）が上限576MiBに収まります。

## 破棄の条件

- 新しい写真をデコードする前、見本の session を作る前、kept に移した後、解析の bytes を足した後に、持つ物＋これから来る物が上限を超えていれば手放します
- 手放す順は、見本の session → 開いている写真の先回りの解析 → 保っている写真（古い順。解析は compact bytes に移す）→ 解析の compact bytes（古い順）です。開いている写真は手放しません
- 補助の worker は、今の物理量＋補助の worker の見積もりが合計に収まるときだけ作ります。収まらなければ、その先回りは作りません。この Worker で作ると描画を止めるからです。補助の worker を作れない環境では、何も手放さずに上限に収まるときだけ、この Worker で作ります（#129 の先回り）
- 書き出しは見積もりを足して判断します
  - 手放さずに合計に収まれば、そのまま同じ Worker で描きます
  - 収まらなければ、上の順に手放してから描きます
  - 開いている写真だけにしても合計に収まらない場合、PC の wasm は使い捨ての worker で描いて終わらせ、OS に返します。保っている物は手放さないので、書き出しの後も編集は速いままです
  - スマホは一時的な山を低く保つほうを優先し、同じ Worker で全部手放して描きます
  - 使い捨ての worker を作れない・起きない・失敗したときは、同じ Worker で全部手放して描きます
- 確保に失敗したときは、今までどおり開いている写真以外を全部手放して1回だけやり直します
