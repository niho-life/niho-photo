# レンズ補正: 手動の歪み・周辺光量と、色収差・フリンジの除去（developSettings v9）

Issue #45。段 2（wasm の `niho-develop`）に、手動の歪み・周辺光量のスライダーと、色収差の自動除去・フリンジの軽減を足した（crate 0.23.0）。右パネルの効果の群の下に「レンズ」の節を出す（PC のみ。スマホの全画面編集層には出さない）。Lightroom のプリセット（XMP）のレンズ補正の項目も取り込む。

プロファイル（レンズの撮影データ）による歪み・周辺光量の補正は作らない（オーナー決定 2026-10-21）。Mac の RAW の sidecar（`apple-raw-linear`）が作業コピーを作るときに既に焼き込んでいる（Sony は埋め込み値で歪みと周辺減光、Panasonic と未登録の機種は Core Image で歪みだけ）うえ、作業コピーの上では切れない（2026-09-29 のオーナー決定）ので、段 2 に「プロファイル補正のスイッチ」を足すと二重に補正する。手動の値はその上の微調整として当てる。lensfun は使わない（データの使用条件の判断は別）。

## 保存形

`developSettings.lens`。全部が既定ならキーを書かない。

```json
{
  "v": 9,
  "lens": {
    "distortion": 12,
    "vignetting": 30,
    "vignettingMidpoint": 50,
    "removeChromaticAberration": true,
    "defringe": {
      "purple": { "amount": 40, "hueLo": 30, "hueHi": 70 },
      "green": { "amount": 0, "hueLo": 40, "hueHi": 60 }
    }
  }
}
```

- `distortion`: -100〜100（既定 0）。正で樽型（線が外へ膨らむ）を直し、負で糸巻き型を直す。
- `vignetting`: -100〜100（既定 0）。正で四隅を明るくする。`vignettingMidpoint`: 0〜100（既定 50）。小さいほど中心の近くから効く。
- `removeChromaticAberration`: 真偽値（既定 false）。写真から横方向の色収差を推定して除く。
- `defringe.purple` / `defringe.green`: `amount` 0〜100（既定 0）、`hueLo` / `hueHi` は Lightroom の色相の目盛り 0〜100（`hueLo <= hueHi`。既定は紫 30〜70・緑 40〜60）。
- 欠けた項目は既定。知らないキーは `unknownKey`、数でない値は `invalidType`、範囲外は `outOfRange`、色相の逆転は `invalidRange`。
- 画を変える値（歪み・周辺光量・色収差の除去・フリンジの量のどれか）があれば `v` は 9（ほかの機能の条件より大きい版）。中点・色相の範囲だけでは版を上げない（古い reader が描く画は変わらない）。v9 を知らない reader（crate 0.22.0 以前、`niho-develop-render` 0.16.0 など）は `unsupportedVersion` で断り、レンズ補正を落とした画を作らない。

## 処理の位置

段 2 の再標本化（`frame.rs` の `working_image`）の逆写像の、元の画に最も近い端にレンズを置く。

出力画素の中心 → 切り抜き（角度つき）→ 補正後の枠の点 → 遠近の逆 `F⁻¹` → **レンズの逆（歪み・色収差）** → 元の画（90° 回転・反転の後の枠）→ Catmull-Rom 4×4（線形光）を 1 回。

- 歪み・色収差のあるレンズは、角度 0・遠近なしでも「角度つき」と同じ経路（Turned）で描く。周辺光量とフリンジだけなら経路は変えず（Aligned。全体を縮小して切った画と一致する契約のまま）、窓に後から当てる。
- 周辺光量は再標本化の画素に掛ける線形光のゲイン、フリンジは再標本化の直後の窓で除く。どちらも局所処理（ハイライト・シャドウ・テクスチャ等）・色の補正・効果の前。ホワイトバランスより前の、作業コピー（線形 ProPhoto）・オリジナル（線形 sRGB）の色の空間で当てる。
- 修復（#44）の印は元の画を直すので、その後にレンズを当てる。
- 出力の大きさ・切り抜きの座標は変わらない（切り抜きの道具の枠は、レンズと遠近を当てた補正後の枠の上）。
- 適応統計（ハイライト・シャドウ等が読む写真全体の統計）は、幾何と同じく幾何の前の写真全体から読む（周辺光量のゲインは含まない）。
- 部分補正（マスク）の位置は、遠近と同じくレンズの歪みを追わない（作業画像の座標のまま）。

### 歪み

枠（`W × H`）の中心 `c`、半対角 `R`。出力の点の半径 `r`（`ρ = r / R`）は、元の画の半径 `r_src = z · r · (1 − a ρ²)` の点を取る。

- `a = distortion / 100 × 0.2`（±100 で隅が ±20%）。
- `ρ > 1`（窓の余白と、遠近で空いた隅だけ）では `ρ = 1` の接線で延ばす（`z R ((1 − a) + (ρ − 1)(1 − 3a))`）。`|a| ≤ 0.2` で写像は単調。
- `z` は出力のどの画素も写真の内側を指すようにする倍率。`a ≥ 0` は 1（隅は内側を取る）、`a < 0` は `1 / (1 − a)`（隅が外を指すぶん写真を拡大し、隅を写真の隅に合わせる。Lightroom の「切り抜きを制限」と同じ考え）。そのため歪みでは黒縁・引き延ばしの縁が出ない。切り抜きの「余白を埋める」（遠近）とは独立に効く。
- `a < 0` で拡大するぶん、JPEG / PNG は `1 − a` 倍だけ大きく開く（`rasterDecodeSize`）。縮小は中心の倍率 `z` を見て、出力 1 画素がおよそ枠 1 画素になるよう事前縮小する。

### 色収差

赤・青の画は緑に対して中心から少し拡大・縮小している（緑の半径 `r` の縁が赤では `s r`）。赤は緑の点 `p` に対して `c + s_R (p − c)`、青は `c + s_B (p − c)` を取る（チャンネルごとに別の点で Catmull-Rom）。`z` は `max(1, s_R, s_B)` でも割り、赤・青の隅も写真の内側に収める。

`s_R`・`s_B` は Session が元の画（開いたままの写真。幾何・白・補正の前）から 1 回だけ推定し（`lens/chromatic.rs`）、プリセットの見本・自動・色の取得の Session と共有する。

1. 解析の画: 長辺 2560px 以下ならそのまま、それより大きければ線形光の Lanczos 3 で長辺 2560px へ縮める（画面の作業画像と同じ縮め方。原寸の書き出しでも画面と同じ推定になる。#133）。
2. 縁の候補: 約 640 列の格子で、半対角の 20〜97% にあり、緑の平方根の勾配（±2px）が 1px あたり 0.012 以上で、向きが放射方向（接線方向の成分が放射方向の半分以下）の点。強い順に 6000 点まで（同点は位置の順）。
3. ずれ: 各点を通る放射方向の線で R・G・B を 0.5px おきに ±5px 標本化（双一次）し、緑の縁の山（緑の符号の微分）の塊を 1.5px 広げた範囲で、各チャンネルの微分の重心を縁の位置とする。緑の段差が明るい側の 30% 以上、そのチャンネルが同じ向きに緑の 0.25〜4 倍の段差（中立に近い縁）、山が窓の端に掛からない縁だけを使う。`ずれ = 赤（青）の位置 − 緑の位置`、縁の半径は緑の位置。
4. 当てはめ: チャンネルごとに `ずれ = (s − 1) r` を原点を通る直線に、中央値の傾きから始めて Tukey の biweight（`c = 4.685 × 1.4826 × MAD`、0.02px 以上）の反復重み付き最小二乗 8 回で当てる。重みの合計 24 以上・傾きが標準誤差の 3 倍以上・隅でのずれ 0.25px 以上のときだけ採り、ほかは 0（補正しない）。±1% で止める。
5. 縁の無い・一様な・ノイズの・色収差の無い写真では 0 になり、スイッチを入れても画は変わらない（スイッチだけでは窓の経路にも入らない）。

### 周辺光量

緑の点の、元の画の半径 `ρ` によるゲイン `2^(ev · t²)`。`ev = vignetting / 100 × 1.5`（±100 で隅が ±1.5 EV）、`t = clamp((ρ − ρ0) / (1 − ρ0), 0, 1)`、`ρ0 = 0.9 × vignettingMidpoint / 100`（中点 50 で半対角の 45% から効き始め、隅で最大）。EV で対称なので、`+v` と `−v` は打ち消し合う。描画では `ρ` 0〜1 の 8192 段の表を線形補間する（正確な値との差は 1e-6 以下）。

### フリンジ

再標本化の直後の窓（線形光）で（`lens/fringe.rs`）:

1. 明るさ `L = √Y`（`Y` は線形 sRGB の Rec.709 輝度。作業コピーの ProPhoto はこのためだけに sRGB へ）。
2. 縁の強さ: `L` の中心差分の勾配を `smoothstep(0.03, 0.09)`。
3. 縁の近く: 半径 `r` の正方形の中の最大値（`r` はこの倍率の枠の長辺 512px あたり約 1px、1 以上、窓の余白の内側）。長辺 3327px までは 1〜6 で、原寸（6000px で 12）でも写真の上で画面（2560px で 5）と同じ範囲に届く（#133）。
4. 色相: 線形 sRGB の六角形の色相 `atan2(√3/2 (G − B), R − (G + B)/2)`（赤 0°・黄 60°・緑 120°・青 240°・マゼンタ 300°）。Lightroom の目盛り `u` の換算は、紫 `225 + 1.35 u`°（0〜100 → 225〜360°。既定 30〜70 は 265.5〜319.5°）、緑 `60 + 1.2 u`°（60〜180°。既定 40〜60 は 108〜132°）。範囲の中は 1、外は 10° で 0 へ。彩度が輝度の 3〜8% より低い画素（もう中立）は除く。
5. `w = min(1, 紫の量/100 × 紫らしさ + 緑の量/100 × 緑らしさ) × 縁の近さ × 色の濃さ` で、その画素自身の輝度の灰色へ寄せる（`rgb + w (Y − rgb)`、`Y` はその空間の輝度）。

縁から離れた大きな紫・緑（花・葉）は変えない。紫・緑の物の輪郭（強い縁の近く）は、その色の範囲に入れば同じく彩度が下がる（Lightroom のフリンジ軽減と同じ性質）。

## キャッシュ（Session）

- 色収差の推定は写真ごとに 1 回（`OnceLock`）。露光・白・幾何を変えても取り直さない。`Session::lens_stats()` が推定した回数を返す（テスト用）。
- 窓の鍵（`frame_key_with_lens`）にレンズの値（推定した倍率を含む）を入れる。レンズを変えると窓を作り直し、露光などの変更では作り直さない。
- 決定論: 固定順の `f32` / `f64` 演算・`sqrt`・`libm` だけで、native と wasm の結果は bit 一致する（`tests/lens.rs` を wasm でも回す）。

## XMP

- 読み: `LensManualDistortionAmount` → `distortion`（同じ符号。Lightroom の正が樽型を直す向きかは未校正）、`VignetteAmount` / `VignetteMidpoint`（レンズの手動の周辺光量。効果の `PostCropVignette*` とは別）→ `vignetting` / `vignettingMidpoint`、`AutoLateralCA`（0 / 1）→ `removeChromaticAberration`、`DefringePurpleAmount` / `DefringeGreenAmount`（Lightroom の 0〜20）→ `amount` の 5 倍、`Defringe*HueLo / Hi` → そのまま（逆転は並べ替える）。XMP に無い項目は写真の値のまま。範囲外は丸めて「範囲外の値を丸めて適用」。値が効いていれば `approximate`（NIHO の近似）、0 なら `exact`。
- プロファイル補正: `LensProfileEnable = 1` と `LensProfile*` の名前などは `metadata`（作業コピーで適用済み・JPEG / PNG はカメラの補正のまま）。`LensProfileEnable = 0`（補正を切る）と、オンで量（`LensProfileDistortionScale` など）が 100 以外のときは `unsupported`（作業コピーの補正は切れない・量を変えられない）。取り込みの「使えない項目」の知らせは、`LensProfileEnable = 0` を Lightroom の既定と同じ値として出さず（主の項目が 0）、オンで量を変えたプロファイルだけ「レンズ補正」と出す。旧方式（PV2010）の `Defringe` は 0 以外なら「フリンジ軽減」。
- 書き出し: 群 `lens` で 10 本（整数。フリンジの量は 0〜20 の目盛り）を書く。プロファイル補正は書かない。レンズと撮影の特性なので既定の群に入れる（Lightroom の「レンズ補正」を含むプリセットと同じく、当てると写真のレンズ補正を置き換える）。
- 適用量（0〜150%）: 歪み・周辺光量・中点・フリンジの量は写真の値からプリセットの値へ線形に動かして範囲で止める。色収差の除去と色相の範囲は 0% より上でプリセットのもの。
- 同梱のプリセット `colorful` は `AutoLateralCA="1"` を持つので、当てると色収差の除去が入る（v9）。

## 画面

- 右パネルの効果の群の下に「レンズ」の節（既定で閉じる。開閉は端末に覚える）。上から、作業コピーに焼き込まれたプロファイル補正の状態（読み取り専用の 1 行）、歪み・周辺光量・中点のスライダー、「色収差を除去」のスイッチ、見出し「フリンジ」の下に紫・緑のスライダー。見出しの横の「初期化」はレンズ補正の全部（中点・色相の範囲も）を外す（既定のとき押せない）。
- 状態の行は作業コピーの meta の `_source.lensCorrection.mode` から: `apple`「歪み補正: 撮影データのプロファイルで適用済み（Apple）。手動の値はその上の微調整です」、`embedded`「歪み・周辺光量の補正: …（埋め込み）…」、`none`「歪み補正: なし（この機種のプロファイルはありません）」。オリジナル（JPEG / PNG）・meta を読めない写真には出さない。
- スライダーは補正の部品のまま（ドラッグの間は速い描き方、離したら取り消しの 1 単位。ダブルクリックで既定。中点は周辺光量が 0 の間は押せない）。スイッチは押すと確定。補正するものが見つからない写真でも何も起きないだけ（注記は出さない）。フリンジの色相の範囲はスライダーに出さず、XMP から入ったまま保つ。
- 節は、wasm が `v: 9` の小さな設定を `validateSettings` で通すとき（`supportsLens`）だけ出す。
- 補正のコピー / 貼り付け・プリセットはレンズ補正を運ぶ（写真の中身ではなくレンズと撮影の特性）。右パネルの「初期化」と「補正前」はレンズ補正を外す。自動はレンズ補正を変えない（当てた画で測る）。
- 修復の道具の「幾何なし」の画は、画素を動かすレンズ補正（歪み・色収差）も外す（ポインタの位置 = 印の座標）。周辺光量・フリンジは残す。
- 旧エンジン（Photo Bench）の形へは戻さない（`developSettingsToEditSettings` は画を変えるレンズ補正があれば null）。

## 確かめたこと（合成画像）

- 歪み: 既知の樽型・糸巻き型（`distortion` ±30 の写像の逆）を与えた線のカードで、横線の曲がりの最大が 6.9 / 6.1px → 0.003px。
- 周辺光量: 既知の落ち（`vignetting` 60・中点 30 の逆）を与えた一様な画で、線形光の誤差 3e-8（原寸）・6e-5（半分に縮小）。8bit の Session の描画で四隅と中心の差が 34 → 2 段階。
- 色収差: 赤 +0.3%・青 −0.25% の放射状のずれを与えた枝のカード（640×427）で推定 +0.296% / −0.247%（8bit の PNG で +0.293% / −0.243%）。外周の `|R − G| + |B − G|`（線形）の平均が 0.0268 → 0.0019。2560×1707 の枝のカード（+0.25% / −0.2%）で +0.231% / −0.190%。一様・単色・グラデーション・ノイズ・灰色のノイズ・色収差の無い枝のカードでは推定 0 で、スイッチを入れても描画は bit 一致。
- フリンジ: 縁の紫・緑の画素の彩度（8bit の最大 − 最小）90〜107 → 0。縁から離れた紫・緑の正方形の中と空は bit 一致。紫だけを入れると緑のフリンジは残る。
- 遠近・角度・切り抜きとの組み合わせで、出力画素の元の点が「幾何の点 → レンズの式」と一致する（1e-9）。
- レンズの無い設定・中点や色相の範囲だけの設定は、変更前の HEAD と 324 枚の描画（raster / niho-13 の raster / 実写の fixture / raster の作業コピー / 署名済み RAW の作業コピー × 12 の設定 × 大きさ・品質、サムネイル、単発、色の取得、`rasterDecodeSize`）で hash が一致した。
- 時間（native、2560×1707、窓の作り直し）: 色収差の推定 約 8ms（写真ごとに 1 回）。歪みの再標本化 約 350ms・色収差 約 410ms・両方 約 510ms（角度補正の再標本化 約 305ms・遠近 約 360ms と同じ経路）、1280px のプレビューで 約 115〜155ms。周辺光量だけ 約 13ms、フリンジ 約 90ms（1280px で 約 20ms）。露光などのつまみの描き直しでは窓を作り直さない（Session の 1280px の描画 約 37ms のまま）。

## 制限

- 実写真・実 RAW での効果は未確認（合成画像だけで確かめた）。色収差の推定は中立に近い強い縁の多い写真を前提にし、縁の少ない写真では補正しない。
- Lightroom の実測による校正は未実施（歪み・周辺光量の大きさと向き、フリンジの色相の目盛り・量は NIHO のモデル）。`LensManualDistortionAmount` の正が Lightroom で樽型を直す向きかも未確認。
- 歪み・色収差の再標本化は 2560px の原寸で数百 ms かかる（角度・遠近と同じ）。歪みのスライダーのドラッグ中は 1 コマごとに窓を作り直す。
- 部分補正（マスク）の位置はレンズの歪みを追わない。Upright の推定は歪みを直す前の枠の線で行う。
- Mac のネイティブ書き出しは同梱の `niho-develop-render`（`apps/camera/develop-sidecars.lock.json` の版。現在 0.16.0）で描く。sidecar を 0.23.0 以上に上げるまで、画を変えるレンズ補正のある設定（v9）はネイティブ書き出しで `unsupported_settings` として断られる（レンズ補正を落とした画は出ない）。
- スマホの全画面編集層には節を出さない。
