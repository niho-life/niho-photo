# 修復: なぞって周囲から埋める（developSettings v8）

Issue #44。前半でエンジン（設定の形・周囲から埋める処理と「写す」・Session への組み込みとキャッシュ・wasm の能力プローブ・TS の設定の読み書き）を足した（crate 0.24.0）。後半で画面（右端の帯の「修復」・ブラシの重ね描き・印の一覧・写し元のつまみ。PC のみで、スマホの全画面編集層には出さない）を足した。修復の間は写真を「幾何なし」（回転・反転・遠近・角度・切り抜きを外し、色と印は当てる）で表示し、ポインタの位置がそのまま印の座標になる。生成 AI による削除と人物の自動検出は対象外.

## 保存形

`developSettings.heal` は描いた順の印の配列。印が 1 つでもあれば `v` は 8（ほかの機能の条件より大きい版）。印が無ければキーを書かない（恒等）。

```json
{
  "v": 8,
  "heal": [
    { "id": "m1", "mode": "remove", "radius": 0.012, "feather": 0.5, "points": [[0.10, 0.31], [0.24, 0.33], [0.41, 0.36]] },
    { "id": "m2", "mode": "clone", "radius": 0.03, "feather": 0.3, "points": [[0.62, 0.70]], "source": [-0.12, 0.02] }
  ]
}
```

- `points`: `[x, y]` は 0〜1。EXIF の向きを当てた後、ユーザーの 90° 回転・反転・遠近・角度・切り抜きの**前**の写真の幅・高さに対する割合。幾何を後から変えても印は写真の同じ場所に当たる。
- `radius`: ブラシの半径。長辺に対する割合（0.002〜0.25）。点列を結んだ線から半径 + 0.5px 以内の画素が埋める穴。
- `feather`: 0〜1。縁から `feather × radius / 2` だけ内側までを smoothstep で写真へ戻す（0 は 1px の縁取りだけの硬い縁）。半径の内側の半分は必ず全部埋まる。
- `mode`: `remove`（消す: 周囲から埋める）/ `clone`（写す: 別の場所から写す）。
- `source`: `clone` の写し元。印からの相対位置（各 -1〜1、幅・高さに対する割合）。写し元が写真の外に出るときは写真の中へ押し戻す。無ければエンジンが周りで最も似た場所を選ぶ。`remove` では保持するだけで読まない。
- `id`: 1〜64 文字の ASCII。重複は `duplicateId`。画素の結果には効かない（名前を変えても計画し直さない）。
- 上限: 印 64 個・1 つの印 512 点・合計 2048 点（座標を 5 桁で書くと 1 点 18 バイト前後。設定の 64KiB に十分収まる）。上限超え・知らないキー・数でない値は形の誤り、範囲外・点が空は `validate` の誤り（`outOfRange` / `emptyPoints` / `tooMany`）。
- 5・6 はほかの機能の版。v8 を知らない reader（crate 0.21.0 以前、`niho-develop-render` 0.16.0 など）は `unsupportedVersion` で断り、印を落とした画を作らない。

## 描く位置

修復は最初に当たる。Session は「今の元の画」（JPEG / PNG・raster / unsigned RAW の作業コピーは元の画そのもの、署名済み RAW〔niho-3/4/5/7/11〕と niho-6/10 の応答はその prepared master）を印で直した写しを持ち、窓・幾何・縮小・局所処理・色の補正・効果はすべてその写しから描く。印の無い設定は従来と同じ経路で、出力は bit 一致する。

- 署名済み RAW・niho-6/10: 埋め方（どこから写すか）は元の画（master と同じ大きさ。縮小した master のときはそれと同じ大きさに縮めた元の画）の上で決め、master に当てる。露光・白・CNR などで master が変わっても、印の計画は探し直さず当て直すだけ（1 回あたり数 ms〜数十 ms）。
- 適応統計（ハイライト・シャドウ等が読む写真全体の統計）は直した写しから読む（印が変わったら捨てて取り直す）。幾何のある・無い描画で同じ統計を共有するため、どちらも直した写しにそろえた。niho-3/4 の解析（CNR・応答の係数）と niho-6 の解析は直す前の元の画から読む: 局所の修復では大きく変わらず、印を描くたびに重い解析をやり直さないため（その分のキャッシュは印を含まず、決定論的）。
- 窓・縮小・統計・局所処理・色ポイントの面は、直した写しが変わったときに捨てる。
- 「補正前」（`beforeSettings`）は印も外す（元の写真と比べるため。幾何は保つ）。
- 自動（`autoSettings`）は印を外して測り、結果に印を戻す（印は局所で、自動が読む明るさの分布はほとんど変わらない）。Upright の推定も印の前の画で行う。
- 単発の描画（ブラウザの JPEG / PNG の書き出し `render` / `exportJpeg`）は、デコードした原画をその場で直して描く（写しを作らない。Session と同じ画）。Mac の `niho-develop-render` は Session の経路で描く。

## 埋め方

### 印の形（`heal/shape.rs`）

画素の座標は `(x W, y H)`、半径は `radius × max(W, H)`。手で描いた密な点列は Douglas–Peucker（0.25px）で間引いてから使う（形は 0.25px 以内で変わらない）。各画素の中心から線分列までの距離を印の近くだけで計算し、穴（距離 < 半径 + 0.5）と混ぜ方（`feather`）を決める。点が非常に多く大きい印では距離を粗い格子で取り、双線形で補う。

長い印（電線など）は、長辺 `max(384, 6 × 半径)` px のタイルに分けて順に埋める（タイルの穴の外接矩形 + `max(2 × 半径, 24) + 20` px の文脈だけを見る。前のタイルの埋めた結果は既知、後のタイルの穴は未知として扱う）。斜めの電線でも、計算と記憶は印の周りの帯の分だけになる。

### 消す（`heal/complete.rs`）

多重解像度の PatchMatch（Wexler の EM 型の補完）。

- 空間: 線形光の平方根（知覚的に近い明るさ）でパッチの距離を測り、票（埋める値）は線形光で平均する。
- 解像度の段: 文脈ごと半分に縮め、穴が数パッチ幅になるまで（`ceil(log2(2 × 半径 / 6))` 段、1〜8）。粗い段の画素は既知の子の平均、子に穴があれば穴。最も粗い段は穴を縁から内へ玉ねぎ状に埋めた値と乱択の対応から始める。
- パッチ 7×7。各パスは走査順を交互にし、隣の対応の伝播・下の「周期」の候補・半径を半分ずつにする乱択探索を試す。写し元のパッチは文脈の中に丸ごと入り、穴に掛からないもの。穴の今の推定値は写真の 1/4 の重みで比べる（縁の写真に合わせる力を強くする）。
- EM: 各段で「PatchMatch → 穴の各画素をそこを覆うパッチの写し元の重み付き平均で更新」を繰り返す。重みは `exp(-誤差 / (2 × 平均誤差))`。回数は最も粗い段 5 回（初回 3 パス・以降 2 パス、全域の乱択）、中間 3 回（1 パス、半径 6）、最も細かい段 2 回（1 パス、半径 3）。段を細かくするときは対応を 2 倍して引き継ぐ。
- 周期（He & Sun の dominant offsets）: 穴の周り（`max(2 × 半径, 16)` 以内）の写真のパッチ（最大 4096 個を間引いて）を、パッチ 1 個分以上離れた最も似たパッチに PatchMatch で対応させ、構造のある（分散が中央値の 1/4 を超える）よく合う（距離が中央値以下）対応のずれの頻度を数える。上位 8 個（2px 以内の重複は除く）が対応の 4% 以上を占めれば、煉瓦・タイル・格子・縞の周期とみなし、すべての段のすべてのパッチで候補として試す。さらに最も細かい段では、縁から幅優先に各パッチが周期の中から縁の写真と埋めたところに最も合うもの（隣のずれを優先）を選んで写した始まりからも EM を回し、エネルギー（パッチの距離の合計）の小さい方を採る。粗い段で模様が潰れる大きな穴でも、目地の位相がそろう。
- 計画に残すのは最も細かい段の対応（ずれと重み）だけ。当てるときは、その対応で今の画から票を取り直す（同じ画なら計画のときと同じ値）。

### 写す

- `source` があれば、その画素数のずれ（四捨五入。写す範囲が写真の外に出ないよう押し戻す）。
- 無ければ、穴の周り `4 × 半径 + 8` px 以内で、穴の周りの帯（幅 `0.5 × 半径`、2〜32 px）が最も似ているずれを、穴が 16 セル程度になるまで縮めた格子で全探索し（写す範囲が穴と重ならないものだけ。同点は近い方）、原寸で 1 セルの範囲を詰める。合う場所が無ければ「消す」で埋める。

### 色合わせと混ぜ方

穴の外側 2px の帯で、写真と埋めた値（消す: その画素への票、写す: 写し元の同じ位置）の差を平方根の空間で取り、`2 × 半径` 程度の粗い格子で平均し（±0.15 に制限）、push-pull で穴全体へなめらかに広げて埋めた値に足す（境目の明るさ・色の段差を消す。写す場所の明るさが違ってもなじむ）。最後に `alpha × 埋めた値 + (1 − alpha) × 写真` を線形光で混ぜる。

### 大きな印と上限

穴が 2^20 px を超える・1 つのタイルの文脈が約 157 万セルを超える印は、2・4・8… 倍に縮めた写しで埋め、原寸へ双線形で戻して混ぜる（その分柔らかくなる）。印の計画は 48MB までを新しい順に保持する。病的な入力でも時間は有限（原寸 2560px で、半径 25% の印 1 秒、64 個の印 1.8 秒、512 点のジグザグ 0.7 秒）。

原寸の書き出し（#133、`tests/heal_full_size.rs`。合成の芝、Mac Studio・release、1 回の `heal_in_place`＝書き出しの decode の後の仕事）の時間と、写真の上に増えるヒープの最大:

| 写真 | 小さな印 16 個（半径 0.4%） | 全幅の電線（64 点・半径 0.3%） | 大きな印（半径 10%） | 最大の印（半径 25%） |
|---|---|---|---|---|
| 24MP（6000×4000、写真 274MiB） | 0.16 s・2MiB | 1.0 s・20MiB | 0.26 s・67MiB | 1.3 s・149MiB |
| 61MP（9504×6336、写真 689MiB） | 0.32 s・4MiB | 2.3 s・54MiB | 0.27 s・142MiB | 1.2 s・115MiB |

増えるヒープは写真 0.54 枚分以下（Session はこのほかに直した写しを 1 枚持つ）。大きな印は縮めた写しで埋めるので、61MP でも時間は 24MP とほぼ同じ。試験は写真 2 枚分のヒープ・60〜120 秒を上限にする（`--ignored`。4000 万画素を超える写真を開くのは #132）。

### 決定論

固定回数の反復・固定シードの xorshift・固定順の `f32` / `f64` 演算と `libm` だけなので、同じ入力は同じ出力になり、native と wasm はビット一致する（`tests/heal.rs` を wasm でも回す）。

## キャッシュ（Session）

- 直した写しの鍵: 元の画の種類（元の画そのもの、または master の鍵）と、印の内容・大きさの指紋。色・露光などのつまみを動かしても、JPEG / PNG・作業コピーでは直し直さない。署名済み RAW で master が変わったときは当て直すだけ。
- 印の計画の鍵: 画像の大きさ・その印の内容と、その印が読む範囲に書く前の印の鍵。印を足すとその印だけを計画し、印を消す・動かすと、それに重なる後の印だけを計画し直す。計画はプリセットの見本・色の取得の Session と共有する。
- `Session::heal_stats()` が計画した印の数・直した回数を返す（テスト用）。

## 公開面

- wasm: 口は増やさない。`render` / `Developer.render` などが設定の `heal` を読む。Worker は起こした wasm に `validateSettings` で印が 1 つある小さな `v: 8` の設定を確かめさせ、通ったときだけ `ready` に `heal: true` を付ける。画面は `supportsHeal()` が true のときだけ修復の道具を出す（後半）。
- TS: `develop-heal.ts`（形・上限・読み取り）、`develop-heal-editing.ts`（画面が使う純関数: `readDevelopHeal` / `addDevelopHealMark` / `appendDevelopHealPoint` / `updateDevelopHealMark` / `removeDevelopHealMark` / `clearDevelopHeal` / `canAddDevelopHealMark` / `developHealUsage`）。直した印だけを書き換え、知らないキーは保ち、印が 0 個ならキーごと消し、変化が無ければ同じ参照を返す。形の版は書いた結果から決め直す。
- 補正のコピー / 貼り付け・プリセット・自動は印を運ばない（写真の中の傷の位置は写真ごと。貼り付け先・当てる前の写真の印を保つ）。右パネルの「初期化」は色だけを戻し、印は保つ。印のある写真は「何も当てていない」に数えない（`isNeutralDevelopSettings`）が、色の補正（`isNeutralDevelopColors`）には数えない。Photo Bench の形（`developSettingsToEditSettings`）へは戻さない。
- XMP: プリセットの書き出し（`settingsToXmp`）は印を書かない（`notWritten` にも入れない）。Lightroom の `RetouchAreas` は読まない（対象外）。プリセットを当てても印は当てる前の写真のまま。

## 確かめたこと（合成画像）

- 空のグラデーションを横切る電線（太さ 1.5〜5px、点 33 個の線）をなぞる: 穴の中の線を引く前の画との差は RMSE 0.16〜0.28 段階・最大 1 段階（8bit sRGB）。
- 640×480 の縞・斜めの縞・格子に不規則な染み（半径 40px、ブラシ 56px）: 線を引く前の画と一致（相関 1.0）。ノイズのある煉瓦: 目地の位相がそろう（残る差はノイズの分）。
- 単色の背景: 背景色（最大 1 段階）。
- 写す: 写し元とほぼ一致（芝のノイズの分の平均 2.8 段階、相関 0.998）。写し元が写真の外に出る指定は押し戻され、写し元を選ぶのも決定論的。縁の段差は写真の模様と同程度で、`feather` を大きくすると小さくなる。
- 90° 回転・反転・遠近・角度・切り抜きを後から変えても、印は写真の同じ点に当たる。
- 印の無い設定は変更前の HEAD と 82 枚の描画（raster の Session・サムネイル・色の取得・自動・単発・raster / 署名済み RAW の作業コピー）で hash が一致した。
- 縮小プレビュー（半分の大きさで開いた写真）と原寸で直してから縮めた画: 穴の外は一致、穴の中は写した芝の粒の違いだけ（RMSE 約 7 段階・平均色の差 0.3 段階以内）。
- 時間（native、2560×1707、半径 1.5%・長さ 10% の印）: 1 つの印の計画 約 80ms、4 つを一度に 約 330ms。印を 1 つ足したときの 1 枚の描画 約 100〜120ms。露光だけを変えたときは計画も当て直しもしない。全幅の斜めの電線 約 0.46 秒。

## 制限

- 実写真・実 RAW での品質は未評価（合成画像だけで確かめた）。人物・看板など大きな物を消すときの質感（芝・木の葉・人工物の組み合わせ）は実写を見て調整する余地がある。
- 粗い段で潰れる大きな規則模様は、周期を拾えない写真（模様が穴の周りに少ない・遠近で歪んだ壁）では目地が 1〜2px ずれることがある。
- プレビュー（作業画像の大きさ）と原寸の書き出しでは写す画素が違うので、細かな模様の粒は一致しない（色と明るさはそろう）。
- 非常に大きな印は縮めて埋めるため、原寸の書き出しでは柔らかく見える。画面の大きさ（2560px）へ縮めて比べると、原寸で埋めた画の方が穴の中の粒が残る（24MP・半径 10% の印で、隣の輪に対する粒の比 画面 0.39・原寸を縮めた画 0.55。ΔE00 の mean 1.18・p99 4.2 は粒の違い。`examples/export_fidelity.rs`、#133）。
- Mac のネイティブ書き出しは同梱の `niho-develop-render`（`apps/camera/develop-sidecars.lock.json` の版。main は 0.27.0、配布中の Mac アプリは 0.16.0）で描く。印のある設定（v8）を原寸へ渡すのは、renderer が `niho-develop-render capabilities` に答えて v8 を読めると言うときだけ（#131）。答えない古い renderer では原寸のカードを押せず、更新の案内を出す（印を落とした画は出ない）。
- 一覧のタイルで補正後のプレビューが無い写真は、印を当てない（補正前のまま）。
