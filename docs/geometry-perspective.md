# ジオメトリ: 遠近の補正と Upright（developSettings v7）

Issue #46。前半で Lightroom の切り抜きパネルの中の「変形」（Transform）の手動のスライダーと「切り抜きを制限」（Constrain Crop）を、エンジンの射影変換と切り抜きの道具の「ジオメトリ」の節として足した。後半で傾き・遠近の自動検出（Upright の 自動 / 水平 / 垂直 / フル。下の「Upright」）を足した（#88の手動補正 crate 0.22.0 に続く crate 0.23.0）。レンズの歪み（#45）とガイド付き Upright は対象外。

## 保存形

`developSettings.geometry` に 3 つのキーを足す。どれも既定値なら書かない（遠近の無い設定の形・描画・版は従来と同じ）。

```json
{
  "v": 7,
  "geometry": {
    "crop": { "left": 0.05, "top": 0, "right": 0.95, "bottom": 1 },
    "perspective": { "vertical": -32, "horizontal": 0, "rotate": 1.5, "aspect": 0, "scale": 100, "x": 0, "y": 0 },
    "constrain": true,
    "upright": 0
  }
}
```

- `perspective`: XMP の `crs:Perspective*` と同じ単位・範囲。`vertical` / `horizontal` / `aspect` / `x` / `y` は -100〜100、`rotate` は -10〜10（度）、`scale` は 50〜150（%）。恒等は 0・0・0・0・100・0・0。欠けた項目は恒等の値、知らないキー・数でない値は形の誤り、範囲外は `outOfRange`。
- `constrain`（「余白を埋める」）: 真偽値。遠近が無いときは描画に効かない。
- `upright`: Lightroom の `PerspectiveUpright`（0 オフ / 1 自動 / 2 水平 / 3 垂直 / 4 フル / 5 ガイド付き）。0〜5 の整数で、保持するだけで描かない（Upright の結果は `perspective` に書く。値は押しているボタン）。

遠近が恒等でないときだけ `v` は 7 にする（ほかの機能の条件より大きい版）。5 と 6 はほかの機能の版で、この版のエンジンと画面は読まない。v7 を知らない reader は設定を補正なしとして読み替えず、閲覧のみにする（色ミキサーの v4 と同じ）。`constrain` と `upright` だけでは版を上げない（古い reader が描く画は変わらない）。

## 変換のモデル

Lightroom はスライダーの値から変換への式を公開しておらず、実測データも無い。NIHO は次の物理モデルで定め、Lightroom の実測による校正は未実施の近似とする（同じ値で Lightroom と同じ画にはならない）。

枠（90° 回転・反転の後）の画素座標を、中心を原点・長辺 `L` で割った座標 `u = (x − W/2)/L`、`v = (y − H/2)/L`（y は下向き）にし、枠から「補正後の枠」（枠と同じ大きさ）への写し方を `F = T · S · A · K · R`（右から当てる）とする。

- `R`（回転）: `rotate` 度。写真が画面で反時計回りに回る向きを正とする（`u' = u cos + v sin`、`v' = −u sin + v cos`）。角度補正 `angle` の正と同じ見え方。
- `K`（垂直・水平）: 焦点距離 `f = 50/36`（長辺 36mm に 50mm）の仮想カメラの前で写真の面を傾けたときの台形。`q' = q / (1 + p·q)`、`p = −(horizontal, vertical)/100 × tan 40° / f`。スライダーは傾きの正接に比例し、±100 で ±40°。中心は動かず中心の倍率は 1（遠近で縮んだ奥行きは戻さない。それは縦横比で直す）。`vertical` の負で上が広がり（下から見上げた建物の収束を直す向き）、`horizontal` の正で右が広がる。
- `A`（縦横比）: 横を `1.25^(aspect/100)` 倍、縦をその逆数倍。正で横に伸びる。
- `S`（拡大・縮小）: 中心の回りに `scale/100` 倍。
- `T`（オフセット）: `x/100` × 枠の幅の半分だけ右、`y/100` × 枠の高さの半分だけ下。

描画は各出力画素の中心を逆写像 `F⁻¹ = R⁻¹ · K⁻¹ · A⁻¹ · S⁻¹ · T⁻¹`（各段の厳密な逆を固定の順に `f64` で合成）で枠へ戻す。三角関数は `libm` なので native と wasm の結果は bit 一致する。

## 描画

順序は 90° 回転・反転 → 遠近 → 角度補正 → 切り抜き → 出力サイズ。切り抜き（`crop`）と角度は補正後の枠の上の座標で、補正後の枠は枠と同じ大きさなので、切り抜きの式・出力サイズ・画面の枠の計算はそのまま使える（Lightroom も変形の後に切り抜きを当てる）。

- 遠近のある幾何は、角度 0 でも「角度つき」と同じ経路（`frame.rs` の Turned）で描く。出力画素の中心 → 切り抜き（角度つき）→ 補正後の枠の点 → `F⁻¹` → 枠の点 → Catmull-Rom 4×4（線形光）を 1 回。角度と遠近を 1 回の再標本化にまとめる。
- 縮小: 出力 1 画素が切り抜きの中心で枠の何画素に当たるか（`F⁻¹` の Jacobian の行列式の平方根 σ）を見て、枠を出力の縮小率 `k` の `k / max(σ, 1)` に事前縮小する（`scale` を下げても折り返しを作らない。拡大はしない）。
- 局所処理の半径は補正後の枠の長辺 × `k`、適応統計は幾何の前の写真全体から読む（従来どおり）。窓の余白も従来どおり。
- 写真の外を指す点（遠近で空いた隅）は写真の端の画素で埋める。段 2 の処理に透明が無いこと、一定の色は色・明るさの補正で色づくこと、端の画素なら局所処理に硬い境目を作らないことから。「余白を埋める」で切り落とすのが前提。
- 部分補正（マスク）の面も同じ写像（切り抜き → 余白を埋める → `F⁻¹` → 反転・回転を戻す）で出力の画素を作業画像へ戻す（`local_render::SourceMap`。TS の `geometryOutputToSource` と共有 fixture で一致。`docs/local-adjustments.md`「座標」）。
- 遠近が恒等の設定（`perspective` 無し・恒等の値・`constrain` / `upright` だけ）は従来と bit 一致する（変更前の HEAD と、合成画像・実写の fixture・作業コピーの 234 の描画で hash 一致を確かめた）。
- Session の窓のキー（`frame_key`）に遠近と `constrain` を入れ、遠近だけを変えても描き直す。
- JPEG / PNG を開く大きさ（`rasterDecodeSize`）は、`scale` が 100 を超えるときその分だけ大きく読む。

## 余白を埋める

補正後の枠の上で、補正した写真が占める凸多角形（枠の 4 隅を `F` で写した四角形と枠の共通部分）を作り、切り抜きをその中に収める（`perspective.rs` の `constrain_corners`）。

1. 切り抜きがすでに収まっていればそのまま。
2. 切り抜きの角度と縦横比は保ち、収まる最大の倍率 `s ≤ 1` を二分法（60 回）で求める。各倍率で収まる中心の範囲は、多角形の各辺を箱の張り出し分だけ内側へずらした半平面の共通部分（Sutherland–Hodgman で切る）。
3. その倍率で、元の中心に最も近い中心に置く（中心がもう収まるなら動かさない）。

既定の切り抜き（枠全体）なら「枠と同じ縦横比で写真の中に収まる最大の長方形」になり、写真をずらしたときも中央で縮めずに動かして大きく残す。保存する `crop` は書き換えず描くときに収めるので、スイッチを切ると元の切り抜きに戻り、遠近を変えると収め直す。画面の枠も同じ計算（`develop-perspective.ts`）で収めた箱を見せ、ドラッグで動かした箱も収めてから確定する。`geometryOutputSize` も収めた後の大きさを返す。

## Upright

写真の直線から、遠近の 回転・垂直方向・水平方向 を推定する（`upright.rs`。依存は足さない）。結果はスライダーの値として `perspective` に書くので、描画・保存・XMP は手動の補正と同じ。

### 推定

1. **枠**: 作業画像を 90° 回転・反転した枠（遠近の前）。輝度（`0.2126 R + 0.7152 G + 0.0722 B`、負は 0）を長辺 1024px 以下に面積平均で縮め、平方根（おおよそ知覚の明るさ）にして 99.5 パーセンタイルが 255 になるよう伸ばす（最大値の 10 倍まで）。切り抜き（`crop`）は見ない（枠全体から推定する）。
2. **線分**（LSD に似た自前の検出）: ガウシアン（σ 1）→ Sobel の勾配。勾配が 5.2（0〜255 の 1 画素あたり）以上の画素を強い順に種にし、勾配の向き（符号込み）が領域の平均から 22.5° 以内の 8 近傍をつなぐ。主軸が長辺の 2.5% 以上、主軸に直交する広がり（勾配で重み付けた RMS）が 2px 以下、外接長方形の半分以上を埋め、平均の勾配が主軸を横切る領域を線分とする。曲がった領域は 11.25°・5.6° でつなぎ直す（短く真っすぐな断片になる）。
3. **縦・横の線**: 出力の軸（角度補正 `angle` を差し引いた向き）で垂直から 25° 以内を縦の線、水平から 25° 以内を横の線とし、長さで重みを付ける（長い順に最大 2048 本）。
4. **当てはめ**: 描画と同じ写し方 `F`（縦横比・拡大・X / Y は既定）に角度補正の回転を続けた写像で各線分の両端を写し、軸からのずれ（角度の正弦）を残差にする。粗い格子（回転 1°・垂直 / 水平 10 刻み。長い 256 本で）で始点を選び、Tukey の biweight（5°・3°・2°）の反復重み付き Levenberg–Marquardt で詰める。当てた写像で縦・横の線を選び直してもう一度詰める（強く収束した写真の端の線を拾う）。値はスライダーの範囲（回転 ±10°、垂直・水平 ±100）に収める。垂直・水平にはごく弱い 0 への引き（100 で損失 0.05）を足し、線の配置で決まらない値を大きくしない。
   - 水平（2）: 回転だけ（縦と横の線の両方から）
   - 垂直（3）: 回転と垂直方向（縦の線から）
   - フル（4）: 回転・垂直方向・水平方向（両方から）
   - 自動（1）: 3 つを当て、すべての縦・横の線のずれ（2° の Tukey の平均）に、パラメーターの数の重み（垂直 0.03・フル 0.05）と補正の大きさ（`0.1 × ((垂直/100)² + (水平/100)²)`）を足した値が最も小さいものを選ぶ（Lightroom の自動と同じく、合う中で単純で小さい補正）
   - 線の足りない向きのパラメーターは 0 のまま（フルは垂直へ、垂直は水平へ落ちる）。当てたモデルを `mode` で返す
5. **誤った補正をしない**: 2° 以内に合う線が、使う向きごとに長辺の半分以上の長さ・3 本以上（水平は合わせて 2 本以上）・その向きの線の長さの 30% 以上ないと、補正しない（恒等・確からしさ 0・`reason: "noLines"`）。ノイズ・円・グラデーション・なめらかな模様・傾きのそろわない幹では補正しないことをテストで固定した。範囲いっぱいで止まった補正は確からしさを半分にする。
6. **確からしさ**（`confidence`、0〜1）: 合う線の長さ（長辺の 2 倍で 1）×（1 − ずれの平均）。

値は 0.01 に丸める。`f32` / `f64` の決まった順の演算と `libm` だけなので native と wasm の結果は bit 一致し、同じ入力からは同じ値になる（`tests/upright.rs` を wasm でも回す）。長辺 1024px への縮小と線分の検出は 1 画素あたり定数回で、当てはめに渡す線分も 2048 本までなので、ノイズの多い写真でも時間は増えない（native で 1 回 30〜40ms。12MP の作業画像の縮小込み）。

`angle`（切り抜きの角度補正）は変えない。推定は角度補正を差し引いた出力の向きで行うので、角度で手直し済みの写真で押しても二重に回さない（回転は「必要な回転 − angle」になる。範囲を超えると止まる）。

### 公開面と画面

- wasm: `Developer.estimateUpright(settingsJson, mode)` → `{ perspective: { vertical, horizontal, rotate, aspect, scale, x, y }, mode, confidence, lines: { vertical, horizontal }, reason? }` の JSON。Worker は `sampleColor` と同じ単発の問い合わせとして描画と同じ列で順に処理する。口があり遠近（v7）も描ける wasm だけ `ready` に `upright: true` を付け、画面は `supportsUpright` が true のときだけ 4 つのボタンを出す。
- 「ジオメトリ」の節の先頭に 自動 / 水平 / 垂直 / フル（高さ 44px。読み上げ名は「名前（何を直すか）」、押している Upright は `aria-pressed`）。押すと今の設定で推定し（その間は 4 つとも押せない）、見つかれば遠近（回転・垂直・水平。縦横比・拡大・X / Y は既定に戻す。Lightroom の Upright も変形のスライダーを上書きする）・`upright`・「余白を埋める」の on を 1 回の確定（取り消しの 1 単位）で書く。見つからなければ書かずに「傾きを検出できませんでした」の 1 行（`role="status"`）。当てたときは読み上げだけ。
- 押しているボタンをもう一度押すと Upright を切る（遠近を恒等に戻し `upright` を外す 1 単位。「余白を埋める」は on のまま）。手でスライダーを動かすと `upright` を外す（その値から手で直す）。推定の間に切り抜きを出た・写真が替わった・90° 回転・反転・角度を変えたら、結果は当てない。
- プリセット・補正のコピーの扱いは前半のまま（Upright は既定の群に入れない）。

## XMP

- 読み: `Perspective*` を `geometry.perspective` に当てる（範囲外は丸めて「範囲外の値を丸めて適用」）。当てる前の切り抜き・回転は写真のまま。恒等の値は `exact`、ほかは `approximate`（NIHO の近似モデル）。`CropConstrainToWarp`（0 / 1）は `constrain` に当てる。`PerspectiveUpright` は `upright` に保持して描かない（オンなら `unsupported`）。Upright の計算値（`UprightTransform_*` など `Upright*`）は Upright がオンなら `unsupported`、オフなら保持のみ。`UprightVersion` は保持のみ。
- 書き出し: 群 `transform` で 7 本と `PerspectiveUpright`・`CropConstrainToWarp` を書く。幾何は写真ごとのものなので既定の群には入れない（画面の「プリセットとして保存」はまだ選べない）。
- 適用量（0〜150%）: 7 本は写真の値からプリセットの値へ線形に動かして範囲で止める。`upright` と `constrain` は 0% より上でプリセットのもの。
- 取り込みの「使えない項目」の知らせは「Upright の自動計算」だけになる（変形の手動のスライダーは使える）。

## 画面

- 切り抜きの道具（PC）の「反転と回転」の下に「ジオメトリ」の節（既定で閉じる。開閉は端末に覚える）。垂直方向・水平方向・回転・縦横比・拡大・縮小・X オフセット・Y オフセットのスライダー（範囲・単位は XMP どおり。回転と X・Y は 0.1 刻み）と「余白を埋める」のスイッチ。見出しの横の「初期化」は遠近・余白を埋める・Upright だけを戻す。節の先頭は Upright の 自動 / 水平 / 垂直 / フル のボタン（上の「Upright」）。
- スライダーは補正のスライダーと同じ作法: ドラッグの間は編集内容だけを替えて速い描き方で描き直し、離したら取り消しの 1 単位として確定する。遠近は幾何の一部なので、切り抜きの［キャンセル］（Esc）は入ったときの遠近にも戻す。↶ で戻せる。
- 切り抜きの間の写真は、遠近を当てた補正後の枠全体（余白を埋めるは外す）で、切り抜きの枠はその上に描く。
- 90° 回転・反転は、結果の見た目が回る・鏡映するように遠近も写す（`F' = M F M⁻¹`。回すと垂直と水平・X と Y が入れ替わり縦横比の符号が反転、鏡映は水平・回転・X〔左右〕または垂直・回転・Y〔上下〕の符号が反転）。
- 節は、wasm が `v: 7` の小さな設定を `validateSettings` で通すとき（`supportsPerspective`）だけ出す。
- 補正のコピー / 貼り付けは幾何を運ばないので、遠近も運ばない。プリセットは変形（遠近・Upright）だけを入れ、自動は幾何を変えない。

## 制限

- Lightroom の実測による校正は未実施（向き・大きさは上のモデルの選択。`horizontal` の正負、`aspect` の正負、`y` の正負は Lightroom と逆の可能性がある）。
- Mac のネイティブ書き出しは同梱の `niho-develop-render`（`apps/camera/develop-sidecars.lock.json` の版。main は 0.26.0、配布中の Mac アプリは 0.16.0）で描く。v7 の設定を原寸へ渡すのは、renderer が `niho-develop-render capabilities` に答えて v7 を読めると言うときだけ（#131）。答えない古い renderer では原寸のカードを押せず、更新の案内を出す。
- 補正後のプレビューが無い写真の一覧のタイルは、遠近を CSS で再現しないので幾何を当てない（補正前のまま）。
- スマホの切り抜きの道具には節を出さない。
- Upright の推定は合成画像（既知の射影を当てた建物風の画像・線の無い画像）でだけ確かめた。実写真での精度（レンズの歪みで曲がった線・複数の面の横の線・木や人物の多い写真）は未確認。90° 回転・反転した後も `upright` の値は押したボタンのまま残す（遠近の値は回転に合わせて写す）。
